Single-package Maven module (`org.opentfc.diag.lite`) packaged as a plain `jar` (no OSGi/AMP manifest) registered via `atlassian-plugin.xml` as one `javax.servlet` servlet. Internal layering:
- `DiagLiteServlet` — HTTP entry point; performs auth checks (SAL + Seraph cookie fallback), routes to download or HTML rendering.
- `HostBridgeLite` — guarded facade over Atlassian APIs (`ComponentLocator`, `UserManager`, `PluginAccessor`, `EventPublisher`, `ApplicationProperties`); every host call is wrapped in try/catch so a missing class only degrades the status line, never crashes the servlet. Reads `<home>/logs` by enumerating directory contents against a strict filename regex, never constructing paths from user input.
- `LiteLogStore` — dependency-free in-memory ring buffer (`ArrayDeque<Entry>`, `AtomicLong` drop counter) used for diagnostic events and plugin framework ENABLED/DISABLED hooks.
- `LiteCapture` / `LiteCaptureInstaller` — optional log4j-core hook loaded lazily via `Class.forName("org.apache.logging.log4j.core.LoggerContext")` so the jar stays free of log4j at link time; `LiteRingAppender` and `HomeDirProbe` are supporting helpers.
Dependency direction: servlet → HostBridgeLite/LiteLogStore; HostBridgeLite → SAL/Atlassian event API; LiteCapture → Log4j only on demand. All external dependencies are declared `provided` so the final artifact is ~25 KB and activates even when the heavy main plugin does not.
